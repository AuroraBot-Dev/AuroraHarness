# 定义你的工作方式

Aurora 的工作方式由你决定：用 Agent 定义长期职责，用提示词复用任务表达，用模型与协作流程组合执行能力。

## 从哪里开始

| 想做什么 | 界面入口 | 会改变什么 |
| --- | --- | --- |
| 给不同工作定义专长 | Agent → 新建 Agent | 角色名称、能力描述、执行 Prompt、模型、工具权限 |
| 保存常用任务指令 | 提示词库 → 新建提示词 | 可反复编辑、复制并填写变量的任务模板 |
| 使用自己的模型服务 | 设置 → 模型与协作 | 供应商、凭据引用、模型 ID、上下文预算、Temperature |
| 组合编写与审查角色 | 设置 → 模型与协作 → 预设协作流程 | 单 Agent 或前端编写与视觉审查流程 |
| 连接额外工具 | 设置 → 工具连接 | MCP 功能包与底层 Server 连接 |
| 调整界面风格 | 设置 → 外观 | 系统 / 浅色 / 深色、预设强调色、十六进制颜色 |

建议先配置模型，再创建 Agent，最后选择会话的协作流程。工作台中的任务输入框需要运行时已连接，并已添加本机工作区。

## 切换工作区与对话

工具栏的「工作区」按钮打开或收起面板。面板直接列出工作区，点击名称即可切换，悬停可查看完整路径。上方的添加按钮用于选择文件夹，每行的更多菜单提供重命名与删除。超过 5 个工作区时出现搜索框；选择后会记住当前工作区，「新对话」也在此工作区创建。

下方只显示当前工作区的对话，默认最近 8 条，可展开全部。标题旁的 ＋ 可以在当前工作区新建对话，行尾菜单保留重命名与删除。收起后，工具栏图标与文字仍保留。平板点击「工作区」打开侧向抽屉，手机从底部打开面板；选择对话后自动关闭。

## 创建自己的 Agent

1. 在「设置」登记供应商和模型。配置名称用于显示，模型 ID 要填写供应商实际支持的名称。
2. 打开「Agent」，新建角色，填写能力描述与执行 Prompt。
3. 选择执行模型，设置工具白名单。留空表示仅使用模型推理，`*` 表示全部普通工具。
4. 保存并测试连接。需要供主 Agent 动态委派时，打开「允许主 Agent 调用」。

**能力描述**帮助主 Agent 判断何时委派，**执行 Prompt**规定角色收到任务后如何工作。可以从提示词库追加一段文字，再按角色需要修改。提示词中的变量在 Agent 执行 Prompt 中不会自动替换，请改成固定要求。

在角色卡片的更多操作中复制 Agent，会打开一份可编辑副本，保存后才建立新角色。副本默认关闭动态调用，可以先调整职责和工具权限。运行与配置详情默认收起，需要时展开查看。

启停与编辑从下一轮运行开始生效；正在运行的一轮保留配置快照。子 Agent 继承当前任务的工作区、沙箱与审批策略。文本与多模态模型可执行，向量模型目前仅用于登记。

详细协议与恢复语义见 [Agent 注册与动态委派](agent-registry.md)。

## 建立提示词库

提示词包含名称、简介和正文。首次打开时提供三个可自由修改的起点；删除全部内容后，刷新不会重新填充它们。

使用双花括号保留每次变化的细节：

```text
请审查 {{审查范围}}，重点关注 {{关注方向}}。

阅读上下文后，报告有证据的问题，每条包含文件位置、触发条件、影响和修改建议。
按严重程度排序；没有发现问题时直接说明。
```

点击「使用提示词」，填写识别出的变量，检查完整预览，再点击「填入工作台」。重复变量只需填写一次；填入后仍可修改，**点击发送才会执行任务**。离线时也可以编辑和预览提示词，连接运行时后再发送。

提示词库支持搜索、编辑、复制、删除和 JSON 导入导出。导入会追加内容并生成新 ID，保留原有提示词；同名内容也会作为独立条目导入。整个文件验证通过后才保存，格式错误或存储空间不足时保留原数据。

限制：最多 100 条，单条正文最多 50,000 字符，名称最多 100 字符，简介最多 500 字符；整个库与导入文件最大 2 MB。导出格式：

```json
{
  "version": 1,
  "items": [
    {
      "name": "代码审查",
      "description": "审查指定范围的代码",
      "content": "请审查 {{审查范围}}。"
    }
  ]
}
```

导出文件还包含 ID 与更新时间；导入时以新条目处理。

## 让界面更像你

在「设置 → 外观」选择明暗模式和强调色。除了预设色和取色器，也可以输入六位十六进制颜色，如 `#D53543` 或 `0066CC`，点击「应用」或按 Enter 生效。输入不完整时不会应用。

「表面材质」可以选择磨砂玻璃或纯色表面。磨砂用于导航与输入面板，连续背景中的光影随强调色变化；切换材质后仍保持相同布局。系统开启减少透明度或浏览器不支持背景模糊时，自动使用纯色表面。

强调色会适配当前明暗背景，必要时调整亮度，以保证强调文字和主按钮文字可读。保存的是你输入的原色，因此切换模式后仍会从同一颜色重新适配。

字体优先使用系统自带的苹方 PingFang SC；没有苹方的平台使用本地后备字体。界面包含轻量渐入、悬停与列表过渡；系统开启「减少动态效果」时自动减少动画。

## 数据保存在什么地方

| 数据 | 保存位置 | 如何迁移 |
| --- | --- | --- |
| Agent、供应商、模型、流程和会话历史 | 运行时 SQLite 数据库 | 参照 [数据库说明](database.md) |
| 提示词库 | 当前浏览器或桌面 WebView 的 localStorage | 导出 / 导入 JSON |
| 明暗模式、强调色、表面材质、侧栏偏好 | 当前浏览器或桌面 WebView 的 localStorage | 在各设备分别设置 |
| 未发送的任务草稿 | 当前应用进程内存 | 刷新后不保留 |
| API Key | 环境变量或桌面系统钥匙串 | 在目标环境重新配置 |

浏览器与桌面应用的提示词库不会自动同步，清理站点数据也会清除本地提示词；需要跨设备使用时先导出备份。提示词与导出文件都是普通文本，不适合存放 API Key。

当前协作流程支持单 Agent 与前端编写 / 视觉审查两类；任意节点编排、提示词云同步与自定义主题布局尚未实现。
